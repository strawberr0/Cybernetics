# NIST SP 800-53 Rev 5 — Composer Service Control Mapping

This document maps the composer service's implemented controls to relevant
NIST SP 800-53 Rev 5 control families. It is an **engineering mapping**, not
a formal ATO package; it is intended to make a future FedRAMP / FISMA
assessment straightforward.

Scope: `cmd/composer` + `internal/middleware` + `internal/oidc` + the build &
release pipeline (`.github/workflows/composer-security.yml`).

Status legend:

- ✅ **Implemented & verified** (tests + CI gate)
- 🟡 **Partial** (control covered for the in-scope component, but depends on
  the deployment environment for full coverage)
- ⬜ **Out of scope for the composer** (covered by the broker, orchestrator,
  or operator-supplied infrastructure)

---

## AC — Access Control

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| AC-2 | Account Management | 🟡 | OIDC-backed identity via `internal/oidc`; account lifecycle is delegated to the IdP. |
| AC-3 | Access Enforcement | ✅ | `middleware.BearerAuth` (constant-time) + `middleware.OIDCAuth` (RS256 JWT, issuer + audience + exp). Tests: `TestBearerAuth_*`, `TestVerifier_*`. |
| AC-4 | Information Flow Enforcement | ✅ | Strict CORS allowlist (`middleware.CORS`); no wildcard origin echoed. Test: `TestCORS_AllowlistOnly`. |
| AC-7 | Unsuccessful Logon Attempts | 🟡 | Rate-limited by `middleware.RateLimiter`; lockout policy delegated to IdP. |
| AC-17 | Remote Access | 🟡 | All access is over HTTPS via deployment-supplied TLS termination (Cloud Run / IAP). |

## AU — Audit & Accountability

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| AU-2 | Event Logging | ✅ | `middleware.AccessLog` emits structured JSON for every request (method, path, status, bytes, duration, remote, request_id). |
| AU-3 | Content of Audit Records | ✅ | slog handler enforces canonical fields; `WithRequestID` provides correlation. |
| AU-4 | Audit Log Storage Capacity | 🟡 | Logs go to stdout; storage is delegated to Cloud Logging / GKE log forwarding. |
| AU-6 | Audit Review, Analysis, and Reporting | ⬜ | Operator responsibility (SIEM integration). |
| AU-9 | Protection of Audit Information | 🟡 | Process drops capabilities (`cap_drop: ALL`), runs read-only root FS; logs leave the container via stdout. |
| AU-10 | Non-repudiation | ✅ | Echoed `X-Request-ID` ties client actions to server log entries. |

## CM — Configuration Management

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| CM-2 | Baseline Configuration | ✅ | Reproducible builds: `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, version stamped via `-ldflags`. |
| CM-6 | Configuration Settings | ✅ | All runtime config is env-driven; defaults are documented in `SECURITY.md`. |
| CM-7 | Least Functionality | ✅ | Distroless `static-nonroot` base — no shell, no package manager, no libc. |
| CM-8 | System Component Inventory | ✅ | CycloneDX SBOM generated by syft and attached to the image via `cosign attest`. |

## CP — Contingency Planning

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| CP-10 | System Recovery & Reconstitution | 🟡 | Stateless service; reconstitution is a redeploy of the signed image. |

## IA — Identification & Authentication

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| IA-2 | Identification & Authentication (Organizational Users) | 🟡 | OIDC verifier consumes IdP-issued ID tokens. IdP identity assurance is operator-supplied. |
| IA-5 | Authenticator Management | 🟡 | Bearer tokens are passed via env (`AUTH_TOKEN`) and never logged; OIDC tokens have IdP-managed lifecycle. |
| IA-8 | Identification & Authentication (Non-Organizational Users) | ⬜ | Out of scope — composer does not serve anonymous users. |

## RA — Risk Assessment

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| RA-5 | Vulnerability Monitoring & Scanning | ✅ | CI runs Trivy (filesystem + image), gosec, govulncheck on every push/PR; SARIF uploaded to GitHub code scanning. |

## SA — System & Services Acquisition

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| SA-10 | Developer Configuration Management | ✅ | All changes via PR; CODEOWNERS enforces review; CI gate before merge. |
| SA-11 | Developer Testing & Evaluation | ✅ | `go test -race`, `golangci-lint`, `gosec`, `govulncheck`, Trivy — all run in CI. |
| SA-15 | Development Process, Standards, Tools | ✅ | `.golangci.yml` enforces 14 linters incl. security checks. |
| SA-22 | Unsupported System Components | ✅ | Go stdlib only — no third-party Go dependencies to maintain. |

## SC — System & Communications Protection

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| SC-5 | Denial of Service Protection | ✅ | Per-IP token-bucket rate limit, request body cap, header size cap, server timeouts. Test: `TestRateLimiter_*`. |
| SC-7 | Boundary Protection | ✅ | CORS allowlist, security headers (HSTS, X-Frame-Options DENY, nosniff). |
| SC-8 | Transmission Confidentiality & Integrity | 🟡 | TLS terminated by the deployment ingress (Cloud Run / Load Balancer). HSTS header asserts policy. |
| SC-12 | Cryptographic Key Establishment & Management | 🟡 | OIDC RSA public keys discovered via `.well-known/openid-configuration`; cached with TTL. |
| SC-13 | Cryptographic Protection | ✅ | RS256 JWT verification uses Go's `crypto/rsa` PKCS#1 v1.5 + SHA-256. |
| SC-17 | Public Key Infrastructure Certificates | 🟡 | Trust roots are operator-supplied (the IdP); JWKS x5c chain is parsed when present. |
| SC-23 | Session Authenticity | ✅ | Stateless API; each request is independently authenticated by OIDC/Bearer. |
| SC-28 | Protection of Information at Rest | ⬜ | Service is stateless; no data at rest in the container. |

## SI — System & Information Integrity

| Control | Title | Status | Evidence |
|---------|-------|--------|----------|
| SI-2 | Flaw Remediation | ✅ | govulncheck runs in CI; Trivy fails the build on CRITICAL/HIGH unfixed. |
| SI-3 | Malicious Code Protection | ✅ | Distroless base eliminates package-manager attack surface; build is reproducible. |
| SI-4 | System Monitoring | ✅ | `/healthz` + `/readyz` probes; structured access logs. |
| SI-7 | Software, Firmware, and Information Integrity | ✅ | Container image signed via cosign (keyless OIDC); SBOM attested; provenance attestation enabled in `docker/build-push-action`. |
| SI-10 | Information Input Validation | ✅ | JSON decode + `MaxBody` cap; deploy handler validates required fields. Test: `TestDeployAgent_RejectsMissingFields`. |
| SI-11 | Error Handling | ✅ | `middleware.Recover` returns generic 500 with no stack trace leak. Test: `TestRecover_TurnsPanicInto500`. |
